# 手首ランチャーとアプリ棚の実装詳細

[コンセプト画像5枚](spatial-launcher-ui-samples-20261121.md)を、一つの APK で試せる操作にする。棚・手首設定・姿勢判定は本書、起動の所有と Stop/Recover は[比較計画 §6–8](spatial-launcher-experiment-plan-20261121.md)、装着時の記録は[評価手順](spatial-launcher-evaluation-20261121.md)を使う。以下の設定キーは製品への提案。姿勢と時間の数値は最初に試す値で、Quest の性能値ではない。

### 同時起動と終了時の扱い

棚からの起動は Ubuntu と Termux を合わせて最大20アプリとする。起動中と終了処理中も枠を占有し、ホスト単位の一覧取得やアプリ内の追加ダイアログはアプリ数に加えない。必要なときだけ実行環境を作る。Ubuntu の枠番号はローカルの回収記録とリモートの保存先の両方に使い、従来の第1・第2枠の記録を引き継ぐ。通常終了時は自動回収し、ホスト一時停止時は間隔を空けて同じ接続先と起動記録を再確認する。回収済みの過去の表示を消し、清算前の枠は再割り当てしない。

Termux の前回の終了証明が届いていない間も、認証済みの SSH 接続からアプリ一覧を読み、更新・切断・再接続できる。起動時は回収待ちの枠を保持し、空いている別の枠でカタログの版とアプリを再確認する。元の起動記録を解放するのは、同じ起動元の子プロセスと一致する終了証明を照合できたとき。音声クライアントが残した専用の空の `pulse/` は、セッションを作成した監督プロセスが通常の終了処理で回収する。


棚の表示と起動直前の worker は、同じ使用数・ホスト別の空き枠判定を参照する。20枠目の終了と再利用、主 runtime と追加 runtime の所有境界、テストの範囲は[複数アプリの契約索引](../../../scripts/structure/README.md#複数アプリの終了と枠の再利用)を参照する。

空間棚はタイトルを選んで移動モードに入る。棚にコントローラーのレイを向けてトリガーを押したまま手を動かすと棚が移動し、離した位置で確定する。グリップで SDK が棚をつかむ操作も使える。棚の正面は移動中の視点へ向く。掴んだ瞬間の視点から棚の中心への方向に対して、開始位置より奥へ押す変位は5倍、手前と横方向は等倍。入力元の追跡が失われたときは開始位置に戻し、離して確定した後は空間に留める。

## 2. 利用者が見る棚

1. 「アプリ」「Linuxアプリ」、キーボード、手首の「アプリ」は同じ一覧データを使う。操作パネルの「アプリ」は常に復帰に使える。最初の描画はローカルで行い、SSH 応答を待たない。
2. P1 の左側に「すべてのアプリ」「お気に入り」を置き、右側の最上段に検索とホスト状態、その直下に複数列のカードを表示する。「すべてのホスト」フィルターを削除し、両ホストの結果をまとめて検索する。狭いパネルでは列数を減らす。詳細設定は折り畳む。
3. 設定済みの Termux と Ubuntu に棚のオープン時と手動更新時に並列で接続を試す。一覧の取得中に重複する要求はまとめる。接続できた順に表示する。明示した停止後に同じ更新処理が接続を繰り返すことは避ける。接続で端末窓を生成せず、窓はカードで要求された時に起動する。
4. カードの識別子はホストの保存済み binding とアプリ ID の組。アプリ名と実行先の表示名を常に示す。押して正常に離せば一度だけ起動し、同じカードに起動待ちと失敗理由を示す。カードの三点メニューでお気に入り・配置を扱う。古いカタログは閲覧専用で、別ホストへの振替起動を禁止する。
5. Ubuntu は SSH 先のユーザーに公開された Desktop Entry を GTK・Qt ともに列挙する。Desktop 本体と検証コンテナを別の実行環境として扱い、列挙と実行を同じ環境に結び付ける。Termux は登録アプリにインストール済み GUI の公開 Desktop Entry を加える。起動方式が未対応の項目は理由付きで表示する。0件、未取得、更新失敗、取得済みの件数を区別する。
6. ホストごとに接続、カタログ世代、起動中の要求、回収記録を分ける。一方を回収中にも他方の一覧・起動・入力を使える。失敗時は上端の該当ホストに「×」を表示。右のレイの hover とフォーカス中の右スティック上で理由を表示する。未接続・失敗のホスト名を押すと、そのホストへ接続してアプリ一覧を更新する。取得中は進行状況を表示する。Ubuntu の通信エラーはホストごとに定型の理由を保存し、次の接続時に理由と進行を棚に表示する。棚を開いている間は一時的な切断を2秒から最大60秒の間隔で再試行する。明示切断、認証拒否、ホスト鍵の不一致では自動再試行を止める。この操作は背後のアプリへスクロールを送らない。
7. P1 は前方へ呼ぶ。P2 は取っ手を引いて置き、P3 は置いた位置で再表示する。すべての空間棚でタイトルバーを動かし、右上のピンで固定・解除できる。固定位置がある時はその位置を優先し、明示的な呼び戻しで見失った棚を回収する。永続固定には既存 Spatial Anchor の保存・復元を使い、復元待ちに初期位置で一瞬描画しない。カードの配置は比較計画 §7 の起動要求に対応した main のみに適用する。

### レイアウトと当たり判定

- 棚の初期サイズは 2.4 × 1.5 m（0.1.97 の面積の約4倍）。P1 は視点の前方約1.55 m。文字を読みやすい密度で描画し、追加面積をカードの列と行に割り当てる。
- 円盤は上から時計回りに「アプリ」「動き」「装飾」「呼び戻す」「設定」の5区画。1区画72°、境界左右2°と中心は無操作。表示と当たり判定は同じ区画数から計算する。手首の退出角で隠し、棚自体には閉じる操作を残す。
- 受入時は通常の棚から1回の操作で窓が一つ開くこと、Ubuntu 本体の列挙件数と棚が一致すること、Termux と Ubuntu の両方で窓を開いたまま一方を終了・回収して他方に入力できることを確認する。件数は接続先の現状から取得し、固定しない。棚の固定は同一シーンとアプリ再起動後を別々に確認する。

### アプリごとの起動履歴

カード右端に警告用の固定幅を取り、前回の起動に問題があったアプリに「!」を表示する。カードを選ぶと、棚の手前にアプリ名・ホスト・登録 ID・理由を表示する。「診断ログを見る」で終了コード、シグナル、取得できたスタックを開く。「閉じる」は履歴を保持し、「再試行」でその時点の接続・一覧・空き枠を検査して起動する。再試行した窓の表示や正常終了を確認した時に印を消す。

「再試行」を押せない間は、前回の起動結果の下に現在の理由を表示する。開いている棚では、Ubuntu の終了を確認したら一覧を取り直す。ダイアログを開いたままでも、同じアプリが新しい一覧で起動可能になり、空き枠があれば「再試行」を押せる。

2026-11-23 に Ubuntu 上の PDF Studio 2024 を計測した。X11 では 6.26 秒で最初の窓が開いた。Wayland のみでは 45 秒間窓が出ず、Java のスプラッシュ初期化が X11 の `DISPLAY` を要求した。起動確認の 20 秒は据え置く。アプリが作成した `cache/install4j/jre_version`（0620）については、同じ起動のプロセス終了と出力パイプの EOF を確認し、同一ブート中に製品のヘルパーが専用ディレクトリを回収できた。

履歴の単位はホストとアプリの組。Termux の登録項目は設定ファイルも区別する。同じアプリを並列起動したときは最後に受け付けた起動の結果を使う。別の枠の回収待ち、利用者による停止、起動要求を示すだけの ACK は異常終了の証拠にしない。

Termux の GUI は起動の nonce、セッション、要求に一致する終了記録を使う。棚の一覧取得時に、対応する GUI 実行プロファイルで実行ファイル・アセット・専用の作業場所と照合できた Android クラッシュログがあれば補足する。ログ取得は主棚を開く時や更新時に時間と行数を限定して行う。表示は終了情報とモジュール名・相対位置に絞る。関数名の補足には、その端末の実行ファイルと照合した根拠が必要となる。

## 3. 設定画面と保存

操作パネルと各棚の「手首ランチャー」から同じ設定を開く。保存先は作業版の SharedPreferences `spatial_launcher`。既存の `preset`（STANDARD / SUMMON / PULL / PINNED）は読み書きを継続する。

| 設定（提案キー） | 値と初期値 | 変更時の動作 |
| --- | --- | --- |
| 呼び出す入力（wristInput） | 自動 AUTO〔既定〕／素手 HANDS／コントローラー CONTROLLERS／手首表示オフ OFF | 円盤だけを対象にする。現在の入力方式と使えない理由を表示。OFF でも既存の棚・設定・キー入口は使える |
| 表示する手（wristSide） | 左 LEFT〔既定〕／右 RIGHT | 選んだ側に円盤を一つ出し、反対側で選ぶ。左右を変えても棚の位置は保持 |
| コントローラーの呼出姿勢（controllerUpLeft、controllerUpRight） | 「標準の向き」「今の向きを登録」「標準に戻す」。左右別、初期は標準 | 選んだ側を好きな傾きにして反対側で「登録」を押す。追跡中だけ保存し、その場に「登録しました」。失敗時は理由と以前の値を保持 |
| 棚の表示方式（既存 preset） | 保存済みを優先。初回は従来の「標準」 | 手首入力と独立。標準でも手首の「アプリ」から従来の一覧を開けるよう、作業版の STANDARD 時の手首更新停止を分離する |

旧保存に新キーが無ければ各行の初期値を使う。未知の列挙値・非有限／長さゼロのベクトルは該当キーだけ初期値に戻す。手の向きは追跡座標の履歴や室内の絶対姿勢を保存せず、次節で定める正規化した3成分だけを保存する。「標準に戻す」は選択側の登録値だけを消す。設定変更時は進行中の手首操作を取り消し、次の入力から適用する。接続状態や Linux アプリには副作用を与えない。

## 4. 姿勢から「表示する意図」を判定する

同じシーンの座標系に変換して判定する。手首位置、選ぶ側の ray、入力の発生元（素手／コントローラーと左右）、追跡の有効性、単調増加時刻、ボタン／ピンチの押下・解放を入力とする。初期の円盤は手首近くに置き、面を利用者に向ける。呼び出し角度を変えても円盤の表面は読める向きを保つ。

- **素手**。表示側の手のひらの表から外向きの単位法線と、空間の上向き単位ベクトルとの角度が小さい時を「手のひらを上に返した」とする。左右の符号はアダプター内で揃える。反対側の hand ray と人差し指のピンチで選ぶ。左手首を返しただけで設定が切り替わったりアプリが起動したりする動作は設けない。
- **コントローラー**。既存の Scene.getControllerPoseAtTime と ControllerPose.TrackedBits を照合する。world の上方向を (0,1,0)、追跡 pose の正規化した回転を q とする。登録時は `r = inverse(q) * worldUp` を表示側のローカル座標で保存。毎回 `score = dot(q * r, worldUp)` を求める。未登録時は r=(0,1,0) を試作初期値にし、実機で標準の握りと角度を確認する。この方式は傾き・手首のひねりを登録し、椅子ごと水平に向きを変えても同じ握りで開ける。選択は反対側の ray とトリガーを使う。
- **初期値**。両入力とも score ≥ cos(30°) が連続250 ms で円盤を表示。表示後は score ≤ cos(50°) が連続150 ms で円盤を隠す。中間帯では表示状態を維持し、途中の判定タイマーは条件を外れたらゼロに戻す。フレーム数で時間を数えない。
- **入力源**。AUTO は有効な一組を選ぶ。操作中は同じ入力源に固定し、待機中は現方式が引き続き有効なら維持、初回に両方有効ならコントローラーを優先する。OS が入力方式を報告する場合は実際の active 方式を優先する。片側ずつ異なる方式を組み合わせない。明示した方式が使えない時は「素手を追跡できません」等を表示し、ControlPanel とキーを使える状態にする。
- **SDK 照合**。固定版 0.15.0 の AAR に Scene.getControllerPoseAtTime と TrackedBits があることを確認済み。0.1.94 の debug merged manifest では handtracking 宣言を確認できなかった。素手側は同版の artifact／入力サンプルから実在する palm・ray・pinch・tracking loss の取得元、宣言・権限、座標系と時刻を特定し、最小ビルドと Quest のイベントで照合する。body 用 joint 列挙名だけで手の入力対応済みとしない。利用不可なら setting に理由を表示してコントローラー版の比較を先行し、素手要件は未完のまま追跡する。

判定器は各フレームで「入力源の失効・切替 → 有効な pose と両タイマー → 既存 capture の解放／取消 → 新しい押下」の順で処理する。取消したフレームの残りのイベントは捨てる。AUTO の「有効な一組」は、同一方式で表示側の pose と選択側の ray・押下状態が利用できる組。SDK が active 方式を切り替えた時は旧 capture を取り消して中立を待つ。

## 5. 1操作の始まりと終わり

| 現在 → 次 | 条件・副作用 |
| --- | --- |
| 非表示 → 表示待ち → 表示 | §4 の進入条件。円盤を一つ描画。起動・クリックは0回。表示時すでに押下中なら有効な解放を待つ |
| 表示 → 項目押下中 | 反対側が中立になった後、新しい押下が有効な項目上に来たら入力源・対象・世代を捕捉。狙っている間の説明と押下表示を区別する。保持中は円盤位置を固定 |
| 項目押下中 → 表示／閉じる | 同じ入力源で同じ項目上の正常解放を受けた時だけ1回実行する。外に離せば取消。表示用の姿勢だけで実行する処理は0件 |
| 取っ手押下中 → 配置中 → 棚を表示 | P2 の grab は棚の移動だけを所有する。作業版の開始位置から 0.20 m 以上、視点から 0.60–4.0 m の有効位置で正常解放すると棚を一つ置く。引き始めた後は退出角だけで配置を確定・取消しない。隠れた手・別の手からの release では置かない |
| 操作中 → 取消 | capture に必要な側の追跡失効、古いサンプル、非有限 pose、focus 喪失、pause、scene／入力方式／設定交代。preview と入力所有を破棄し、遅れて来た release を消費。確定済みの棚・アプリを維持 |
| 復帰 → 非表示 | 新しい入力世代で開始。両側の追跡と中立が戻ってから、新しい呼び出し姿勢と押下を要求する |

サンプルの取得元が失効を通知したら直ちに取り消す。試作は最終有効サンプルから150 ms 超の欠落でも同じ扱い。問い合わせた時刻だけ更新して古い SDK サンプルを新鮮に見せない。円盤を閉じるための姿勢判定は押下中だけ保留する。押下中の追跡喪失・focus 喪失は即取消。shell が所有した press/release を背後の Linux 窓へ配送しない。素手のピンチ操作中に Quest のシステム操作が入力を奪った場合も取消とする。

## 6. 実装を渡す単位

各行は一つ前の共通部を再利用する。型・クラスの新設は既存の責務で足りない場合だけ行う。固定 fixture で姿勢・時間・状態を試す JVM テストには実 SDK や SSH を必要としない。

| 順 | 主に変更する場所 | この変更で通す例 |
| --- | --- | --- |
| 1 棚 | ApplicationLauncher / ControlPanel | Ubuntu 認証失敗、Termux 接続可 → 棚は開き両方の理由と操作を表示。同じ棚を再描画しても接続要求は増えない |
| 2 設定と判定 | SpatialLauncher の設定、姿勢と時間の純粋な判定 | 旧 preset 維持。進入30°で249 ms は非表示、250 ms で表示。40°で維持、退出50°で150 ms 後に隠れる。左右の登録を交換しない |
| 3 コントローラー | SpatialLauncher の frame・controller と InputAdapter | 右手首に切替、右の向き登録→左トリガーで1回だけ選択。Linux click 0回。登録中に追跡喪失→以前の値を維持 |
