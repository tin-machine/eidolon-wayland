# 窓とグループの呼び寄せ

- 右Touchで窓を指してAを押し、Aを離すと手前へ呼び寄せる。Aを押したままBを押すと元の位置と向きへ戻る。窓を指していないときもA＋Bで戻せる。
- 呼び寄せ中に同じ対象を選ぶと現在位置を保持する。別の対象を選ぶと、先の対象の復帰を確認してから新しい対象を移動する。
- 単一窓は呼び寄せ中も移動・リサイズできる。移動は一時配置に反映する。通常のリサイズで変更した寸法はそのまま保持する。窓のメニューから「通常の配置にする」を選ぶと、適用済みの一時配置をその窓の通常配置にする。保存の可否は従来どおりアプリとスロットで判定する。
- 既存の同一セッションの窓グループでは全メンバーが相対位置と回転を保って移動する。グループのメンバー編集・配置変更が必要な場合は先にA＋Bで戻す。メンバーの終了や再接続と操作が重なった場合、現在の世代のメンバーで通常配置への復帰を確認する。複数ホストをまたぐWorking Setは[#102](https://github.com/tin-machine/eidolon-wayland/issues/102)で扱う。

## 操作の条件

同時にAとBが押された場合は復帰を優先する。先にBを押して成立した右クリックは維持する。右Touchの識別にはSDKのcontroller種別と右手のattachmentを使う。Aを押した対象はruntime・session・窓・scene・描画世代・入力世代・グループrevisionを保存し、Aを離した時に再照合する。コントローラーの追跡喪失、入力先変更、レイアウト編集中、ランチャーや窓メニューが入力を所有している間は操作を無効にする。

XRフォーカス喪失やActivityの非表示を受けたら、表示が再開した際に通常配置を適用する。

Spatial SDK 0.15は右TouchのAとTriggerを同じ種類の選択イベントでも通知する。製品の窓では右TouchのボタンビットからTriggerの左クリックを配送し、Aによる呼び寄せと重複させない。Eidolonのメニューボタンと他の入力源は従来の配送経路を使う。

正面候補の既定距離は単一窓で1.0m、グループで1.25m、目線より12cm下。設定画面で単一窓の基準距離と高さを調整できる。候補を既存の窓の境界と照合する。移動は約300msで、位置のイージングと回転のSLERPを使う。「動きを減らす」が有効な場合は即時に移動する。通常配置は別に保持し、明示的に設定した場合だけ一時配置を保存に反映する。

呼び寄せ成功は短い振動1回、復帰成功は短い振動2回、拒否・失敗は弱い振動1回。受付と実際の配置確認を分け、SDKの適用結果を確認するまで成功の振動を出さない。

## 検証

```bash
cargo test --locked -p eidolon-core summoned_group -- --nocapture
cargo test --locked -p eidolon-core --lib workspace::tests
```

Hostでは押下時の保存配置と一時配置の分離、相対配置、全メンバーの適用待ち、古いグループrevisionの拒否を検査する。Androidの単体テストは右A/Bの押下・解放・逆順と追跡失効を検査する。Quest実機では、通常のB/Y右クリック・メニューAが維持されること、空間を指してA＋Bで戻ること、別の窓への切替、通常配置の明示保存、グループ全体の移動と復帰、振動の区別を確認する。
